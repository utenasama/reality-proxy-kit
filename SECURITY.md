# Security and sensitive reports

Please report reproducible security issues privately through the repository's GitHub security reporting channel when enabled. If it is unavailable, ask the maintainer for a private channel without including credentials or exploit-sensitive details in a public issue.

Never attach production inventories, SSH keys, private state, database backups, subscription URLs/tokens, client UUIDs, or generated bundles. A redacted diagnostic report and a minimal reproduction using reserved example addresses are preferable.

This is a development candidate. Passing unit tests is not a production deployment or independent security audit. See `docs/acceptance.md` for the current evidence and mandatory release gates.
