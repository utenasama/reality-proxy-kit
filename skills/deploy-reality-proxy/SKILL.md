# Reality Proxy Kit

先读取用户指定工具版本的 `docs/acceptance.md`，再选择工作流。当前开发候选未通过完整发布验收，不能表述为生产可用发行版；缺少公网测试环境时完成离线准备并准确标记未验证项。

定位用户指定的源码检出或正式发行包；如果没有，查找公开仓库 `utenasama/reality-proxy-kit` 的已验收发行及校验清单。不要从 `latest` 安装脚本临时替换内核。skill 自身不包含 CLI，也不依赖作者机器的其他目录。

## 选择工作流

- 首次搭建：读 [部署与技术边界](references/deploy.md)。明确 single/chain、core/panel、remote/local target；只询问会改变实现的缺失项。
- 网站或域名：读 [网站与共享入口](references/website.md)，再读工具包 `docs/website.md`。购买由用户完成，已有授权的普通配置工作继续执行。
- 账户、诊断、迁移、恢复：读 [维护与恢复](references/maintain.md)，再选工具包对应命令。升级单独设计，不当成日常维护。

用 CLI 完成确定性操作。先生成私有状态和可审查计划，再对已授权目标执行；既有明确授权无需重复确认。身份、主机信任或操作范围不明时，先完成可独立进行的离线工作。

## 必须保留的约束

- 服务端 Ubuntu 24.04 amd64、原生 systemd。每节点公共 IPv4；可选入口 IPv6，业务出站 IPv4。SSH 明确密钥、核验过的 known_hosts、machine_id；拒绝未知既有代理。
- single 是一台入口直出；chain 是一入口、一至多个 SS2022 落地，每条路线固定落地。不给链式添加入口直出、自动切换或故障回退。
- core 不需要面板，只输出私有客户端资料；panel 的账户/路线授权以原生 3x-ui 为权威，CLI 通过原生 API 维护。管理员页面仅 SSH 隧道；公网只发布网站和 HTTPS 订阅。
- 保留审核过的旧 X25519 兼容内核。实际核对磁盘、运行进程哈希和兼容环境开关。面板一键更新、官方二进制均不能替换它。
- 通用 VLESS URI、二维码、URI 订阅不加 `fp` / `fingerprint`。专用 Mihomo/Xray 配置保留实现要求的字段。节点更新不要求重导用户的独立分流配置。
- 生成秘密只写入私有目录；不在聊天、日志、issue、提交中输出私钥、UUID、密码、订阅令牌或链接。默认不开完整目标访问日志。
- 恢复/接管保留身份，先备份；恢复到空白候选，不自动覆盖活跃数据库。新协议先审查测试再加入，不自动选择“最新”。

结束时说明实际修改、检验结果、重启影响和仍未验证的事项。服务 active 不等于出口/权限/客户端已验收；没有真实 VPS 或手机证据就保留发布门槛，不要求生产机器冒险补测。
